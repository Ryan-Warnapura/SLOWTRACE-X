# Archive access and reproducibility

Coordinate searches use official NASA/IPAC SIA2 queries for DR1 and QR3, with IRSA TAP as a secondary metadata route. A search records collection coverage, source endpoint, the time the metadata were obtained, and the bounded sample size. It distinguishes an available archive with no matching exposure from a search affected by an outage. Live catalog responses can be reused in memory within a ten-minute window. The original retrieval time is retained.

IRSA SIA and TAP both returned HTTP 502 during the reliability investigation, including for the official example request. The NASA S3 mirror still provided the original products. The earlier index archived 1,339 targeted Level 2 headers. The release adds 12,684 S3 FITS headers sampled across 151 available DR1 and QR3 planning periods, primarily from detectors 1 and 2. The index checks ICRS coordinates against each shortlisted exposure's FITS TAN-SIP solution and detector bounds. For a requested detector that lacks metadata, the application can try the corresponding optical partner's files and only adds a sibling after confirming its own FITS header, detector, and footprint. Exposure pixels are retrieved separately. Refresh the broad sample with `python scripts/sample_s3_archive.py --per-period 56`.

The sample has finite coverage, especially by individual detector. Missing or timed-out metadata requests, malformed metadata, and result caps are reported as incomplete. A completed metadata search can show zero matching exposures for the selected detector, while a failed processing or download request has a separate status. Auto selects one detector for an entire comparison, favoring several time groups and a long baseline. The viewer can try reserve exposures from that detector after failures. Coverage signals describe products found, with quality determined when the frames load.

The image API first attempts a bounded IRSA cutout and can then read the original product from NASA's S3 mirror. It reprojects calibrated IMAGE onto a common TAN grid, propagates flags and variance, and subtracts ZODI when present. Every returned frame distinguishes the original observation epoch from the request or pixel retrieval timestamp. Manual retrieval can use original official Level 2 URLs when the search service is down. An archive result can contain partial edge coverage, which remains masked in the view.

The five recorded examples are separate from live search and are labeled as such. `scripts/capture_examples.py` captures original products for the four examples beyond the opening Barnard packet and chooses a long-baseline near-wavelength pair when available. The packets keep the original processing version and mask policy, so results can be reproduced even after processing updates. The current API records its expanded mask policy and metadata separately.

Validation used two real epochs at each challenge field. Additional arbitrary-coordinate validation retrieved two genuine epochs for M101 (`210.80227°, +54.34895°`, detector 2) and a Barnard offset field (`269.5862°, +4.76883°`, detector 1). An initial offset test used recorded FITS headers for metadata and live NASA S3 data for the images. A later live check verified the offset, M101 and the exact challenge WISE coordinate (`133.795129°, −7.245147°`). Query availability can change independently of FITS availability. See [coordinate validation and provenance](coordinate-validation.json).
